# 以旧换新

以旧换新由买入／卖出记录和双向关联构成。新物品记录完整买入价，旧物品记录回收收入；补款是二者的差额，不再额外追加一笔实付支出。已有买卖记录直接复用，关联多个物品不会复制金额。

## 使用流程

从物品生命周期选择「换新来源」（当前为新物品）或「换新去向」（当前为旧物品），选择已建档的对方物品。一次最多选择 50 件；只建立当前物品与所选物品的关系，不自动生成其他配对。

已有的有效买入或卖出记录只读复用；缺少记录时填写金额、币种、日期和必要的汇率证据。旧物品必须满足现有卖出条件，包括已有有效买入。换新日期、订单号和备注独立于买卖记录，后者保留自己的发生时间。

保存前查看将新增和复用的买卖记录、将建立的关系。保存时再次检查全部对象及指定事件；预览之后记录被更正时返回冲突，不静默替换。所有新增记录和双向关系同时提交，失败全部回滚。

## 生命周期与历史

每对物品产生「换新来源」「换新去向」两条系统中性事件，固定为零，不改变金额统计、取得／卖出状态或持有天数。时间线显示对方名称、规格和跳转链接，并标注无资金变动。

普通生命周期记录也可选填一个关联物品；普通关联不自动生成反向事件。换新事件必须通过专用用例配对创建、更正或取消，不能通过普通记录入口单边修改。

更正关联时同时作废两边原记录并追加替代记录；取消关联追加取消状态的替代记录。默认视图隐藏已取消关联，历史保留原记录和更正链。取消后可重新关联。关联更正和取消不改买卖金额，金额错误使用现有生命周期更正。

关联对象被管理员永久删除后，本物品的历史记录仍保留最小名称／规格快照，显示物品已删除并取消跳转。缺失一端的换新关系不再允许更正或取消，防止重建被删除物品的事件。

## MCP 接入

| 工具 | 用途 | 权限 |
|---|---|---|
| `preview_trade_in` | 读取所选物品、有效买卖记录和待补字段，不写入 | `assets:read` |
| `record_trade_in` | 复用或新增买卖记录，原子建立所选双向关系 | `assets:lifecycle` |
| `correct_trade_in_link` | 原子更正一对关系的对象、日期、订单号和备注 | `assets:lifecycle` |
| `cancel_trade_in_link` | 原子取消一对关系，保留买卖记录 | `assets:lifecycle` |

方向 `source` 表示当前为新物品、选择旧物品；`destination` 表示当前为旧物品、选择新物品。
提交时每件物品明确指定有效买卖事件 ID，或提供新记录的金额、币种、时间和汇率证据。
金额为整数最小货币单位，时间包含时区；嵌套经济记录共用整个换新命令的请求键。
更正和取消携带关系 ID 及预期的两边事件 ID，过期版本返回冲突。

读取事件时返回关联对象与关系状态。普通 `record_event` 和 `correct_event` 可选填
`related_asset_id`；普通更正省略时保留关联，明确传空值时解除。配对事件只能调用专用工具。
真实订单字段由 AI Harness 向用户确认后提交，不进入公共示例或测试夹具。

## 安全与一致性

关联必须发生在同一数据空间，不允许关联自身。稳定请求键保证重试不重复写入；不同请求重复建立已有有效配对时复用关系。并发下仍遵守一次有效买入和卖出的原有约束。

Web 与 MCP 共用应用服务和租户事务锁。事件是历史事实来源，关系不另建可随意改写的业务账本。不会根据名称、备注或订单号推断并批量建立关系。

本功能不涉及补贴拆分、关联金额分摊、赠品取得状态、通用订单附件、3D 或行情估值。
