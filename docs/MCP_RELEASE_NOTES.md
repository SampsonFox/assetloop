# MCP 子版本总结（2026-09-12 UAT 检查点）

范围：从已接受的 UAT `99f733c` 到本次 `dev-mcp` 批次。
这是 UAT 候选说明，不是生产发布公告；不包含其他开发分支的行情或前端改动。

## MCP 现在能做什么

提供 40 个语义工具（22 个读取、18 个写入），与 Web 共用同一个 Go 程序、
应用服务和数据库。完整工具名、参数口径和配置见 [MCP 使用指南](MCP.md)。

| 能力 | 已支持的操作 |
|---|---|
| 物品与目录 | 查询物品/类别/型号；创建和编辑类别、创建型号、保存具体物品；物品建档与买入记账分开 |
| 规格配置 | 查询与维护类型化标签、型号允许标签、外观覆盖；读取完整编辑配置和引用 |
| 生命周期 | 查询历史、记录买入/维修/卖出等已确认事件、更正金额/日期/备注及汇率证据；维护自定义类型 |
| 成本 | 单物品全生命周期成本、租户物品数及精确现金流汇总；不是二手市场估值 |
| 3D 资源 | 查询资源/引用/生效来源，编辑描述及标签，配置外观规则，绑定/解除绑定；删除未引用资源及重试失败清理 |
| GLB 导入 | 给公开 HTTPS GLB 直链，由服务器下载、校验并注册资源；成功后另行绑定 |

标准流程：确认截图字段 → 查询并复用目录/类型 → 保存物品 → 记录事件 →
核对成本；有可用 GLB 时再导入、配置外观和绑定。截图理解由外部 AI 完成，
应用核心不需要模型 API key。所有写入使用稳定 `request_key`，不确定结果重试
必须复用同一键及内容，避免重复创建或记账。

## 本批次改动

- 同进程 Streamable HTTP `/mcp`，默认关闭；启用时要求本地账号认证。
- OAuth/PKCE、同账号授权页、客户端权限范围、短期访问令牌与轮换刷新、
  客户端撤销入口；当前角色与授权范围共同限制权限。
- 修复 Codex 重复相同 `resource`、刷新时重复原 `scope`、登录返回路径、
  授权按钮值及授权页 Origin/CSP 兼容问题，不放宽跨源或扩权校验。
- 管理写入采用事务内持久化幂等回执；修复目录写入未复用事务的问题；
  增加并发、重放、失败回滚和安全错误响应覆盖。
- GLB 下载限制：公开 HTTPS/443、25 MiB、30 秒、最多三次重定向，
  DNS/IP 校验、防内网访问、并发限制；不继承调用者凭证或环境代理。
- 型号图片（Web 功能）：PNG/JPEG/WebP 上传、替换、解除关联及 HTTPS 导入；
  8 MiB/1600 万像素，完整解码校验；无可用 3D 时显示图片，列表显示缩略图。
  图片按型号共享，替换不影响事件和 3D，解除关联保留历史文件。
- 在 MCP 工具和字段 schema 中明确：类型是可复用的行为分类，具体商品/服务名
  写 `notes`。先复用已有类型，仅在无合适类型且用户确认时新增；不依赖旧对话。
- 成对迁移 00015（OAuth）、00016（管理回执）、00017（型号图片），
  保留既有数据，并扩展 SQLite/PostgreSQL 升级及全要素测试。
- 下载包附带 MCP 配置、踩坑记录、本总结和图片指南。

## 明确不包含的能力

- 没有 MCP 图片上传/导入工具，也没有本地文件上传工具；图片走 Web。
- GLB 导入不是网页爬虫，不会从图片轮播生成真实 3D，不支持压缩包、
  登录站点或自动搜索购买模型；URL 可打开也不保证它是有效 GLB。
- `correct_event` 保留原物品和事件类型，不能用它改分类；不能改名共享类型
  来修正某一笔记录。已确认事件仍采用追加式更正，不直接覆盖历史。
- 暂无新旧物品以旧换新关联、通用订单附件、MCP 行情/估值/成员管理、
  stdio、动态客户端注册或本批次公网部署。
- 型号图片不是每个颜色单独绑定的图片；找图必须先看原图核对型号、颜色、
  主体完整性，不能把多配色合集、色块或局部特写当作准确单款主图。

## 验证层次与已知限制

- 已有 Codex 原生 MCP 完整买入→维修→更正→卖出流程证据，见
  [接入与验收记录](CODEX_MCP_ACCEPTANCE.md)；不等同于原生客户端逐一测试全部工具。
- HTTP SDK 全工具场景、OAuth 撤销和刷新、安全下载、BlobStore、迁移及图片操作
  均有自动化覆盖。UAT 合并前必须以本次 PR CI 的双数据库实际运行结果为准，
  不能沿用旧提交的通过结果或把本地 PostgreSQL 跳过算作通过。
- 本地实际图片替换已验证；跨多个屏幕宽度的完整视觉验收、长期原生客户端刷新、
  当前真实授权的撤销和验收数据清理不宣称已完成。保留用户现有账号、授权和数据。
- UAT 合并后由 Package 工作流再验证、构建五个平台包并做发布包冒烟；
  具体状态以关联 PR/Actions 为准。生产发布须另行批准。
